## C语言错误处理

传统的C语言缺乏异常处理的能力，它提供了一种更原始的机制，即：返回一个错误码。

### 错误码与标准I/O

在发生错误时，大多数的libc函数调用返回1或NULL，并设置一个错误代码errno，该错误代码是全局变量，表示在函数调用期间发生了错误。

**errno变量**：

在C语言中，errno是一个全局变量，用于表示发生的错误代码。它定义在<errno.h>头文件中，并由标准库函数在发生错误时进行设置。此外，errno.h头文件中还定义了各种各样的错误代码。比如：

- EDOM：这个宏表示一个域错误，它在输入参数超出数学函数定义的域时发生。
- ERANGE：这个宏表示一个范围错误，它在输入参数超出数学函数定义的范围时发生。

**打印错误信息**：

此外，C语言还提供了perror()和strerror()函数来显示与errno相关的文本消息。

- perror()函数显示传给它的字符串，后跟一个冒号、一个空格和当前errno值的文本表示形式。
- strerror()函数，返回一个指针，指针指向当前errno值的文本表示形式。

使用方法如下：

``` c
fprintf(stderr, "错误号: %d\n", errno);
perror("通过 perror 输出错误");
fprintf(stderr, "打开文件错误: %s\n", strerror( errnum ));
```

**标准I/O**：

C 程序默认提供三种标准流（<stdio.h> 中定义的 FILE* 指针）：

- stdin：标准输入（对应键盘）。
- stdout：标准输出（对应终端屏幕）。
- stderr：标准错误（对应终端屏幕，通常不带缓冲）。

### 防御式编程——断言

断言（Assertion）是一种用于检查代码假设和约束的工具。断言通常用于在代码中插入检查点，以确保某个条件为真。如果断言的条件不满足，即为假，程序会中止执行并报告错误。

**运行时断言**：

断言的目的是在开发和调试阶段捕捉可能的错误和逻辑问题，以便尽早发现和修复它们。它们通常用于验证程序中的前置条件、后置条件和不变式等。

``` c++
// C用#include <assert.h>，C++#include<cassert> 
#include<cassert> 
assert(divisor != 0);
```

**静态断言**：

除此之外，C++ 还引入了static_assert关键字，它在编译时进行静态断言检查，主要用于模板编程中对类型或常量进行静态约束检查。

### 第三方异常处理

由于纯 C 缺乏原生异常处理机制，大型 C 项目常采用以下变体机制：

- setjmp 与 longjmp：实现上下文切换。不过，它会粗暴地跳过中间栈帧，导致局部对象的析构函数无法执行，极易引发资源泄漏，在现代 C++ 中严禁使用。
- 错误对象指针/Result 模式：通过显式传递错误结构体指针（如 GLib 的 GError*）或封装带状态的返回值。

此外，setjmp 与 longjmp 还可以用于实现协程，不过要手动 malloc 或 mmap 避免局部变量被覆盖。

## C++语言异常处理

C++ 的异常处理机制允许程序在检测到错误时中断常规控制流，将控制权安全地转移给上层调用者，实现错误检测与业务逻辑的分离。

### 抛出、捕获与对象传递

**异常抛出**：

C++ 允许程序通过 throw 表达式引发异常。执行 throw 时，编译器会使用该表达式拷贝初始化一个特殊的异常对象（Exception Object）。此时，当前函数会提早退出，throw 后续的代码语句将不再执行。

**异常捕获**：

在 C++ 中，异常处理通常将可能抛出异常的代码置于 try 块中，并通过 catch 子句进行匹配与处理。当异常被抛出后，程序会沿着调用栈向上回溯，执行栈展开（Stack Unwinding），沿途创建的对象会被自动销毁，其析构函数会被正常调用。

```c++
try {
  // 可能抛出异常的代码
  {
    // ...
    throw std::runtime_error("这是一个运行时异常");
  }
} catch (const std::exception& e) {
  // 捕获异常并处理
}
```

在编写 catch 子句时，形参应尽量使用常量引用（如 const std::exception&），这样既能避免对象切片（Object Slicing）导致派生类信息丢失，也能消除不必要的拷贝开销。此外，catch(...) 可以匹配任意类型的异常，通常作为兜底处理，用于捕获所有未被前面 catch 子句匹配的异常

**二次抛出**：

在 catch 块内部，可以通过一条不带任何表达式的单独 throw; 语句，将当前捕获到的异常原封不动地重新抛出，传递给更外层的调用者。

### 栈展开与析构安全

当 throw 触发后，运行时会自底向上沿着嵌套函数的调用链不断查找与该异常匹配的 catch 子句。如果一直未找到匹配的 catch，程序在退出主函数后查找过程终止，进而触发 std::terminate() 终止进程。

在栈展开的过程中，所有已构造的局部对象会严格按照构造相反的顺序（LIFO）被自动销毁。这与 C++ 的 RAII 机制深度绑定，确保了异常跳跃时不会发生资源泄漏。

### noexcept异常说明

noexcept 异常说明：C++11 引入的关键字，用于显式承诺某个函数绝对不抛出异常。

如果编译器确信函数不会抛出异常，它可以省去生成复杂的栈展开元数据（如 ELF 的 .eh_frame 段），从而减小二进制代码体积并加速执行。

例如 std::vector 在扩容重新分配内存时，若元素的移动构造函数被声明为 noexcept，容器会放心地使用移动语义（Move）来提升性能；否则为了保证强异常安全性，容器可能会退化为低效的拷贝操作。
