## 指令集架构

指令集架构（Instruction Set Architecture）是计算机体系结构中与程序设计有关的部分。它包含了基本数据类型、指令集、寄存器模式、寻址模式、中断集、异常处理以及外部I/O等。

软件以指令形式运行在CPU硬件上，而指令系统介于软件和硬件之间，是软硬件交互的界面，有着非常关键的作用。软硬件本身的更新迭代速度很快，而指令系统则可以保持较长时间的稳定。有了稳定不变的指令系统界面，软件与硬件得到有效的隔离，并行发展。遵循同一指令系统的硬件可以运行为该指令系统设计的各种软件，比如X86计算机既可运行最新软件，也可运行30年前的软件；反之，为一个指令系统设计的软件可以运行在兼容这一指令系统的不同的硬件实现上，例如同样的操作系统和应用软件在AMD与Intel的CPU上都可以运行。

### 指令集发展历史

指令系统的发展经历了从简单到复杂，再从复杂到简单的演变过程。现代指令系统在指令内容、存储管理和运行级别控制等方面都产生了一系列变化。依据指令长度的不同，指令系统可分为:

- **复杂指令集架构（Complex Instruction Set Computer，CISC）**：一条指令可以包含若干低端操作，即若干操作集于单一指令中。复杂指令集的特点是指令数目多而复杂，每条指令字长并不相等，电脑必须加以判读，并为此付出了性能的代价。基于CISC架构的处理器有x86、x64家族等。
- **精简指令集架构（Reduced Instruction Set Computer，RISC）**：精简指令集计算机的特点是指令数目少，每条指令都采用标准字长、执行时间短、中央处理器的实现细节对于机器级程序是可见的等等。RISC设计的根本原则——针对流水线化的处理器优化——没有改变。常见的RISC架构有MIPS和ARM等。其中，前者是大学课程的重要教学材料，而后者则在嵌入式处理器中非常流行，占超过90%的市场份额。

### 指令组成

指令系统由若干条指令及其操作对象组成。每条指令都是对一个操作的描述，主要包括

- 操作码（Opcode）：规定指令的具体功能（如算术运算、逻辑判断、数据传输等）。
- 操作数（Operand）：指示操作的目标，涵盖数据类型、寄存器编号及寻址方式（如立即数寻址、寄存器寻址、内存间接寻址等）。

### 运行级别与权限管理

为了实现系统安全和多任务隔离，现代处理器引入了硬件级的运行级别机制。以 MIPS 和 RISC-V 为例，它们一般将 ISA 划分为 3 个特权级别：

- 用户态（User Mode / U级）：权限最低，供普通应用程序运行，只能访问受限的资源。
- 监督态 / 管理者态（Supervisor Mode / S级）：介于用户态与内核态之间，常用于现代操作系统的内核空间或虚拟化管理（如运行虚拟机 OS）。
- 内核态 / 机器态（Kernel / Machine Mode / M级/K级）：拥有最高硬件特权，可以直接控制所有硬件资源、中断和控制状态寄存器（CSR）。

其中，用于内核态的指令集就被称为特权指令系统。它包含了：

- 运行模式定义及状态切换
- 虚拟存储管理
- 异常与中断处理
- 控制状态寄存器（CSR）访问

### 软硬件协同

**编译器自举**：

在高级语言和编译器出现之前，计算机世界是一片荒蛮。

- 机器码时代：最早的计算机（如 ENIAC），科学家是通过拨动开关、打孔纸带，直接把一串串二进制的 0 和 1（机器指令）喂给计算机的。
- 汇编语言时代：人们觉得写 0 和 1 太痛苦了，于是发明了汇编语言（用助记符如 MOV, ADD 代替二进制）。

第一个汇编器是怎么来的？ 是程序员用纯粹的机器码（0和1）一字节一字节手写出来的。有了第一个简单的汇编器后，程序员就可以用汇编语言写出更复杂的汇编器。

回到 1991 年，林纳斯·托瓦兹在赫尔辛基大学的电脑里编写最初的 Linux 核心时，他并不是在一个空白的机器上凭空造物。

- “借鸡生蛋”：现成的操作系统和工具链。
  - 当时的林纳斯有一台 386 PC，上面安装了一个当时教学用的精简 Unix 系统——Minix。
  - 在 Minix 系统里，已经有了成熟的 GCC 编译器（GNU C Compiler，当时 GCC 的早期版本已经是用 C 写的，但它当时运行在 Minix 上）以及汇编器 gas。
- 交叉编译 / 寄生编译：
  - 林纳斯在 Minix 系统上，用 C 语言写出了 Linux 内核的第一行代码。
  - 然后，他直接调用 Minix 里的 GCC 编译器，把这些 C 代码翻译成了 386 机器码。
  - 刚开始编译出来的不是完整的操作系统，而是一个可以引导的二进制镜像。他把它拷到软盘上，重启电脑，看看能不能在裸机上跑起来——这就是 Linux 的诞生。

**应用程序二进制接口**：

应用程序二进制接口（Application Binary Interface，ABI）是计算机底层世界中给编译器和 CPU 遵守的铁律，它规定了已经编译好的二进制代码之间、以及代码与操作系统之间如何安全交互。

## 计算机组成

计算机组成（Computer Organization）

- 冯诺依曼结构：这是最常见的计算机体系结构,它将程序和数据统一存储在同一内存中。CPU可以同时执行和读取内存中的指令。这种结构具有程序可重入性。
- 哈佛结构：与冯诺依曼结构不同,它将程序和数据存储在两个独立的存储单元中。CPU只能执行存储在程序存储器中的指令,无法直接读取或写入数据存储器。代表产品为Harvard Mark I计算机。
- 菲林分类：根据指令集和数据单元进行分类:
  - SISD:单指令流单数据流,标量处理器
  - SIMD:单指令流多数据流,向量处理器
  - MISD:多指令流单数据流,很少见
  - MIMD:多指令流多数据流,像PC机一样工作

## 微架构

微架构（Microarchitecture）是在特定 ISA 规范下实现处理器功能的具体硬件电路与组织设计。

### 流水线设计

- IF（Instruction Fetch）：从内存或指令缓存中取指。
- ID（Instruction Decode）：对指令译码并读取寄存器。
- EX（Execute）：执行算术逻辑运算或计算地址。
- MEM（Memory Access）：访问数据存储器进行读写。
- WB（Write Back）：将结果写回通用寄存器。

### 流水线冒险与冲突

- 结构冒险（Structural Hazards）：硬件资源有限（如同一周期内取指和访存争夺同一总线）导致的冲突。
- 数据冒险（Data Hazards）：指令间存在数据依赖（如后续指令需要前序指令的计算结果），主要表现为 RAW（写后读）、WAR 和 WAW。通常通过前递（Forwarding/Bypassing）机制或硬件暂停（Stall）来解决。
- 控制冒险（Control Hazards）：由于条件分支（如 if-else）导致下一条指令的地址不确定，若处理不当会导致流水线被频繁冲刷。
